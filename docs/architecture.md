# Architecture

Python68K compiles Language Level 0.1–0.5 source through source loading, tokenization, parsing, symbol analysis, bytecode compilation, verification, and a stack VM. The current implementation owns copied source buffers, source spans, indentation-aware tokens, an arena-owned AST, Pratt expressions, recursive-descent statements, suites, parser context checks, deterministic function symbol metadata, stable opcode metadata, bytecode buffers, scalar/string/float constants, names, module and function-body expression/control-flow emission, verifier CFG/stack checks, a verified stack VM, tracked reference-counted strings/lists/tuples/dicts/sets/modules with transactional mutation and cycle rejection, limited attribute/bound-method dispatch, catchable exception objects with a per-frame try stack, an import loader and cache, function/native object foundations, explicit owned-local frame storage, global and builtin lookup/store, verified native `OP_CALL` dispatch, non-recursive and recursive user-function frame switching with explicit returns bounded by the runtime recursion limit, and platform-backed `print` output.

`py68_symbol_analyze` runs ahead of code generation for every function body (and the module body), classifying each name as a parameter, local, or module-global/builtin reference, assigning deterministic local slots, and rejecting nested `def` statements and duplicate parameters. The compiler consumes this classification to emit `OP_LOAD_LOCAL`/`OP_STORE_LOCAL` for locals and `OP_LOAD_GLOBAL`/`OP_STORE_GLOBAL` for module-level and builtin names. Local slots that have not yet been assigned hold the `PY68_VALUE_UNBOUND` sentinel; `OP_LOAD_LOCAL` raises a `NameError`-style runtime error if a slot is read while unbound, matching Python's "referenced before assignment" semantics.

Function definitions compile to nested `Py68Code` objects stored in the parent code object's `nested` array and referenced from the constant pool via `PY68_CONSTANT_CODE`. `OP_MAKE_FUNCTION` builds a `Py68Function` value bound to the enclosing runtime from a nested code constant at module/function execution time.

Global and builtin name resolution is content-based rather than positional: `Py68GlobalEntry` and the builtin table both store `(name bytes, length)` and are looked up by comparing name content, not by a code-object-local constant-pool index. This avoids collisions where two independently compiled code objects (e.g. a function body and its enclosing module) assign the same numeric name index to different identifiers.
